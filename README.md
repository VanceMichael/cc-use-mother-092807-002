# 口岸食品准入查验与退运销毁闭环

贯通进口食品企业注册、货批查验、样品检测和退运销毁。

## 参与方与事实

主要参与方包括海关食品监管人员、境外生产企业、进口商、实验室人员、退运与销毁执行单位。领域资料记录以下已经确认的事实：

- 天津口岸前8个月进出口食品总值1097.9亿元
- 天津海关完成境外生产企业注册审核和检查任务
- 前8个月查获未准入境食品886批次并实施退运或销毁

## 业务约束

- 境外企业和产品资格
- 箱货与食品批次
- 抽样检测链
- 放行和处置
- 整改与风险预警

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/news_context_002.py` 负责读取和校验这些资料。

## 准入查验服务

`src/inspection_service.py` 在领域资料之上实现完整的准入查验闭环：

- 境外生产企业注册与产品资格按版本留痕，申报货批时校验资格；
- 舱单、集装箱、货批与温控记录关联，同一集装箱可拆成多个货批但不得超申报量；
- 风险规则按版本生效，换版只影响之后形成的决定，已放行、退运或销毁的事实不可覆盖；
- 抽样、拆分、留样、复检保持货量与样品去向一致；
- 检测结论由承检实验室提交、非取样人的监管人员确认，一项不合格可只影响部分规格；
- 放行、扣留、退运、销毁按货量互斥，退运销毁须他人批准并以证明闭环；
- 渠道回执幂等，重送返回原结果，编号相同但内容不同则暂停相关批次；
- 企业只能查看自己的材料，跨部门协查按履职范围开放；
- 快照恢复后继续超期样品、待处置货物和整改复核任务；
- 任一放行或销毁决定可还原当时的资格、规则、检测和批准依据。

`tests/test_inspection_service.py` 覆盖上述行为。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
