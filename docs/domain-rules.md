# 领域边界

贯通进口食品企业注册、货批查验、样品检测和退运销毁。

现有领域资料围绕以下边界组织：

- 境外企业和产品资格
- 箱货与食品批次
- 抽样检测链
- 放行和处置
- 整改与风险预警

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

# 准入查验服务规则

服务代码位于 `src/inspection/`，记录全部以 JSON 持久化（`Store`，原子落盘），
重启后可完整恢复现场。以下规则由 `tests/test_inspection_service.py` 锁定。

## 1. 资格与审单规则：版本化、不追溯

- 审单规则集（`publish_rule_set`）和境外企业注册（`register_enterprise`）均为
  只增版本链，每版带生效时点和内容摘要。
- 审单发生时固化**当时有效**的规则版本、规则全文快照与内容哈希；之后换版
  只影响换版后新形成的决定，已放行、退运、销毁决定中的规则快照保持不变。
- 企业注册版本记录状态（在册/暂停/撤销）与获准产品编码。放行决定在签发时点
  重新核验资格：企业被撤销或产品不在获准范围，不得放行。

## 2. 舱单、箱货与批次拆分

- 舱单包含集装箱、封识号和温控记录；货批申报必须挂在舱单内实际存在的集装箱上。
- 同一集装箱可申报多个货批；一个母批可在**查验或扣留之前**按规格拆成多个子批。
  子批货量之和必须恰好等于母批可拆货量，规格不得重复；母批转为 `split`，
  子批共享 `root_lot_no` 以便追溯。
- 整票扣留（集装箱级）覆盖箱内在途全部货批；局部放行前必须先通过
  `narrow_detention` 缩小扣留范围，明确仍被扣留的规格，否则放行与扣留冲突、
  一律拒绝。缩小范围时未被扣留的货批恢复到扣留前状态。

## 3. 样品链与货量守恒

- 任何时点货批满足：`申报货量 = 在库货量 + 在链样品量 + 已耗样品量`，
  每次抽样、出具报告后强制校验，不平即拒绝。
- 抽样货量从在库货量划转；样品可分出子样（留样、复检样），父子样品量守恒。
- 复检必须有足量在链留样，由海关批准后从留样分出复检样；无留样不得复检。
- 检测结论分合格、不合格、无法判定。合格**不自动放行**——取样人无权确认
  最终合格，放行只能由海关签发；不合格转待处置，无法判定转待复检。

## 4. 处置决定：只增不改，依据可还原

- 扣留、缩小扣留、放行、退运、销毁均为只增决定记录；放行/退运/销毁为货批终态，
  任何重复签发或覆盖尝试抛 `ImmutableRecordError`。
- 退运/销毁决定先由海关签发（货批进入待处置），执行单位回填处置证明后才进入
  退运/销毁终态；同一决定只能出具一份证明。
- 每个终局决定按货批固化依据快照：当时的企业注册版本、规则版本与全文、批次单证、
  温控记录、全部样品链与检测报告、前置扣留/缩窄决定、批准人与时点，以及快照摘要。
  `reconstruct_decision` 重算摘要并交叉核对，监管人员可从任一决定完整还原当时依据。

## 5. 渠道回执：幂等与异文暂停

- 同一回执编号重送且内容摘要一致：只返回首次处理结果，不产生新记录。
- 编号相同但内容不同：抛 `ReceiptConflict`，暂停相关批次（同箱货批与同根拆分批），
  并记录暂停前状态；暂停期间不得放行或处置。
- 已放行/退运/销毁的终态事实不被暂停覆盖；人工核查 `resolve_suspension` 后
  各批恢复到暂停前状态。

## 6. 权限按履职范围开放

- 企业（进口商、境外生产企业）只能查看本企业作为当事方的材料；不能注册或签决定。
- 取样人仅有采样、分样、交接权，不能批准最终合格。
- 实验室仅能查看承接了样品的批次，出具检测结论。
- 跨部门协查按授权批次集合（案件范围）开放，范围外不可见。

## 7. 企业整改

- 海关对问题批次开整改并设到期时点；仅当事企业可提交整改材料，
- 海关复核通过或退回；通过后材料不可重复提交。

## 8. 断点恢复

`recover(at)` 在服务恢复后列出并支持继续：

- 超期且未终态的样品（已用尽/废弃的不追踪）；
- 扣留、待检测、待处置、暂停中的货物；
- 未完成或已提交待复核的超期整改；
- 未完成的查验任务。
